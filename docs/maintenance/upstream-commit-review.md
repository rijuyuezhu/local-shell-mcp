# Upstream Commit Implementation Review

This file tracks every upstream commit after the fork point used by Wenrui Huang's first fork-side commit. The review is functional: a commit is covered when the current fork provides the same user-visible behavior or maintenance outcome, even if the implementation lives in different modules or uses a different architecture.

Status values: **Implemented** means the fork covers the upstream behavior; **Implemented (adapted)** means the fork covers it through a different design; **Partial** means the main goal is covered with known differences; **Not adopted** means the fork intentionally does not carry that upstream direction or the commit only applies to obsolete upstream structure; **Recommended** means the upstream change should still be imported; **Split follow-up** means the idea is useful but needs a fork-specific design rather than a direct port; **Deferred** means the feature remains desired but is intentionally queued behind architectural prerequisites or a dedicated migration phase; **Pending** means the commit has been inventoried for the current migration branch but its fork-specific implementation decision is not complete yet.

Human TUI, remaining embedded WebUI screens, Files preview/navigation, and OpenTUI packaging entries marked **Deferred** are an explicit future migration queue, not rejected functionality. Backend prerequisites may be ported independently before those UI surfaces.
